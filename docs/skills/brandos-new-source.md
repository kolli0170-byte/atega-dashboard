# Подключение нового источника к BrandOS

BrandOS — сервер на Node.js (ESM, без фреймворков) + `index.html`. Данные лежат в `data/db.json`. Каждый источник — отдельный коннектор в `lib/connectors/`. Подключение и отключение — только через `.env`.

## Порядок работы

1. **Уточни, какие данные нужны и зачем.** Какие блоки дашборда или решения они закроют (выручка, остатки, расходы, документы). Нужна только чтение? Почти всегда — да.
2. **Найди официальную документацию API** и выпиши: базовый URL, способ авторизации, лимиты запросов, нужные методы и поля ответа. Не угадывай адреса и названия полей по памяти. Если документацию прочитать нельзя, честно пометь коннектор как «по документации, не проверен».
3. **Создай `lib/connectors/<имя>.js`** по образцу существующих:
   ```js
   import { request } from '../http.js';           // таймаут, повтор при 429/5xx, понятные ошибки
   import { isoDay, daysAgo } from '../db.js';
   export const enabled = () => !!process.env.<КЛЮЧ>;
   export async function sync() { /* ... */ return { /* нормализованные данные */ }; }
   ```
   - Возвращай **нормализованные** данные в тех же формах, что уже используются: продажи `{date, article, revenue, payout}`, остатки `{article, qty, inWay}`, операции банка `{date, amount, party, purpose}`, сделки `{id, c, sum, st, src, mgr, d, closed}`, рекламные кампании `{mp, id, name, status, spend, views, clicks, orders, ordersSum, articles, daily}`.
   - Возврат товара — отрицательная выручка, расход денег — отрицательная сумма.
   - Учитывай лимиты API: паузы между пачками, не больше нужного периода (обычно 28–60 дней).
4. **Зарегистрируй источник:**
   - `lib/sync.js` → добавь в `SOURCES` (`name`, `enabled`, `env`) и в `syncAll()`: `run('<key>', x.sync).then(r => r && (db.raw.<key> = r))`;
   - `lib/aggregate.js` → добавь в `ENABLED` и используй через `live('<key>')`, чтобы данные отключённого источника не попадали в цифры;
   - документы → верни из функции массив файлов `{source, name, buffer, mime, from, date, externalId}` и прогони через `ingest()`.
5. **Обнови расчёты.** Если источник закрывает блок, который был «демо», убери этот ключ из `demo` в `buildDashboard()`. Если данные полезны для решений — добавь их в `buildAnalytics()` и в `snapshotForAI()`.
6. **Обнови `.env.example`.** Пустая переменная и комментарий по шагам: где в личном кабинете взять ключ и какие права дать (только чтение).
7. **Интерфейс.** Добавь карточку в `INTEG_META` в `index.html` (`lg`, `bg`, описание). Если нужно — значок в шапке.
8. **Проверь:**
   - `node --check` всех изменённых файлов;
   - сервер запускается без ключа (источник выключен, ошибок нет);
   - на тестовых данных в формате ответа API расчёты дают разумные цифры;
   - ошибка авторизации показывается на странице «Интеграции» понятным текстом.
   Тестовые данные после проверки удали и верни `data/db.json` в исходное состояние.

## Правила

- Ключи только в `.env`. Никогда не отдавай их в браузер и не пиши в лог.
- Не выдавай оценки за факт: если что-то посчитано приблизительно, отметь это (`estimated`) и покажи пометку в интерфейсе.
- Один источник — один коммит или одна задача. Не меняй попутно чужие коннекторы.
- В конце скажи, что проверено на тестовых данных, а что требует проверки на реальном кабинете.

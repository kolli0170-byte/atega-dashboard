# BrandOS «Атега» — дашборд продавца на маркетплейсах

Один экран для владельца бизнеса, который продаёт на **Wildberries, Ozon и Яндекс Маркете**: продажи, реклама, деньги, склад, поставки, отчёты и налоги. Пока источник не подключён, его блок работает на демо-данных с пометкой «демо».

**Рабочая версия:** https://brandos-production-3daf.up.railway.app (вход по паролю команды).

## Что умеет

- **Главная** — KPI, план месяца, прогноз денег на 30 дней, рентабельность каждого магазина и общая, ДРР.
- **Центр решений** — каждое утро собирает решения на сегодня (по правилам или через ИИ Claude).
- **Маркетплейсы** — WB, Ozon, Яндекс Маркет: выручка, прибыль, рентабельность по каждому магазину.
- **Поставки** — планирование FBO: какой товар заканчивается, на сколько дней хватит остатка, в какой кластер и сколько везти.
- **Отчёты** — ОПиУ, P&L, ДДС с выгрузкой в CSV.
- **РНП («рука на пульсе»)** — ежедневные показатели по каналам.
- **Налоги** — черновики деклараций УСН (КНД 1152017), ЕНП-уведомлений и КУДиР по кнопке.
- **CRM, задачи (канбан), документы, интеграции, ИИ-ассистент.**
- Тёмная и светлая тема, адаптивная вёрстка от 375 px до десктопа.

Демо-каталог взят из реального ассортимента «Атега» (замки, уплотнители, компрессоры). Объёмы продаж в демо выдуманы.

## Как устроен

| Часть | Где лежит |
| --- | --- |
| Сервер (Node.js 20+, без фреймворков) | `server.js` |
| Весь интерфейс (HTML + CSS + JS в одном файле) | `index.html` |
| Сбор данных из API | `lib/connectors/*.js` (по файлу на источник) |
| Синхронизация по таймеру | `lib/sync.js` |
| Расчёты дашборда, отчёты, налоги | `lib/aggregate.js`, `lib/reports.js` |
| Центр решений и ИИ | `lib/decisions.js`, `lib/ai.js` |
| Пароль и сессии | `lib/auth.js` |
| Хранилище (JSON-файл) | `lib/db.js` → `data/db.json` |
| Настройки компании, налогов, плана | `settings.json` |
| Деплой на Railway | `railway.json` |
| Исходный промт сборки | `docs/prompt-brandos.md` |
| Скиллы для ИИ-агента | `docs/skills/` |

Ключи API живут **только** в переменных окружения (файл `.env` локально или Variables на Railway). В браузер и в git они не попадают. Ключи маркетплейсов нужны с правами «только чтение».

## Как продолжить работу на другом компьютере

1. Установите [Node.js 20+](https://nodejs.org) и [Git](https://git-scm.com).
2. Скачайте проект:
   ```bash
   git clone https://github.com/kolli0170-byte/atega-dashboard.git
   cd atega-dashboard
   npm install
   ```
3. Создайте файл `.env` по образцу `.env.example`. Минимум — `APP_PASSWORD`. Остальные ключи можно добавлять по мере подключения источников.
4. Запустите и откройте http://localhost:3000:
   ```bash
   npm start
   ```
5. Перед коммитом проверьте синтаксис и расчёты:
   ```bash
   npm run check
   npm run test:calc
   ```
6. Сохраните изменения в GitHub:
   ```bash
   git add .
   git commit -m "что поменяли"
   git push
   ```

В Codex, Cursor или Claude Code дайте агенту прочитать `README.md` и нужный скилл из `docs/skills/` — так он быстрее поймёт проект.

## Деплой на Railway

Проект уже привязан к Railway (сервис `atega-marketplaces`, постоянный диск `/data` для `db.json`).

```bash
npm install -g @railway/cli
railway login
railway link              # выбрать проект и сервис atega-marketplaces (на новом компьютере)
railway up --service atega-marketplaces
```

Секреты задаются на хостинге, не в коде:

```bash
railway variables --set "APP_PASSWORD=..." --set "WB_TOKEN=..."
```

Проверка: `https://<домен>/healthz` должен вернуть `{"ok":true}`. Логи: `railway logs`.

## Основные переменные окружения

Полный список с пояснениями — в `.env.example`.

| Переменная | Для чего |
| --- | --- |
| `APP_PASSWORD` | пароль входа в дашборд (обязателен на хостинге) |
| `SESSION_SECRET` | подпись сессий |
| `WB_TOKEN`, `WB_ADS_TOKEN` | Wildberries: продажи, остатки, реклама |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | Ozon Seller API |
| `OZON_PERF_CLIENT_ID`, `OZON_PERF_CLIENT_SECRET` | реклама Ozon |
| `YM_API_KEY`, `YM_CAMPAIGN_ID` | Яндекс Маркет |
| `TBANK_TOKEN` / `TOCHKA_TOKEN` | банк |
| `AMO_SUBDOMAIN`, `AMO_TOKEN` / `BITRIX_WEBHOOK` | CRM |
| `TELEGRAM_BOT_TOKEN` | приём документов через бота |
| `ANTHROPIC_API_KEY` | ИИ (Центр решений, разбор документов, ассистент) |

## Скиллы, с которыми собирался проект

Лежат в `docs/skills/`:

- `frontend-design` — визуальное направление, типографика.
- `ui-ux-pro-max` — справочник стилей, палитр и графиков.
- `spacing` — сетка 4/8 px, выравнивание.

- `anti-slop` — убирает визуальный шум.
- `ux-audit` — финальная проверка интерфейса.
- `marketplace-api` — справочник API WB, Ozon, банков, CRM, Telegram.
- `brandos-new-source` — как подключить новый источник данных.

## Что ещё не готово

- Остатки по кластерам FBO в демо разбиты условно — нужны складские API.
- Налоговые формы — черновики, сверяйте с актуальными формами ФНС.
- Поля Яндекс Маркета проверить на реальном кабинете после ввода ключей.
